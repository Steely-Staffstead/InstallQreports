    Start with a template

    Choose New in Qanvas to open the template library. You can start with a blank canvas or use a ready-made application/report with embedded sample data.

    The first template collection includes:

    • Tender Pipeline — pipeline board and deadline report with editable embedded tender rows.
    • Project Planner — an editable Gantt plan plus a management progress page.
    • Management KPI Dashboard — a clean executive-report starting point with fictional monthly figures.
    • Public Weather Snapshot — an Open-Meteo example that opens with cached weather values.
    • Nordic Growth Explorer — a World Bank example with cached GDP-growth values.

    What happens when you use a template

    A template is downloaded, verified and opened as a new unsaved Qanvas. Saving creates your own copy; it never changes the published template. The first Save proposes a filename based on the canvas name.

    Every template includes sample data so it remains useful without a connection or network refresh. Replace the embedded rows or edit the source to connect the design to your own data. Public API examples identify the external service and include cached values so they also open when the API is unavailable.

    Qanvas caches the last valid catalog and any downloaded templates locally. Previously downloaded templates can therefore be reused when offline. Refresh checks for additions and updated template versions.

    Add an official template

    Open QanvasTemplateManager from the Visual Studio solution's tools folder. Select the .qanvas file and a preview image, enter the library metadata and choose Add template. The tool creates the immutable documentation/templates/<id>/<version> folder, writes template.json, validates the Qanvas file and rebuilds the catalog.

    Use a new semantic version instead of replacing a version that has already been published. Review and commit the generated files in xlQuerySolution, then select Publish to GitHub to run the normal documentation/template publisher. Publishing requires the authenticated, clean InstallQreports documentation checkout used by the existing release workflow.

    To withdraw a template version, select it under Manage catalog and choose Remove from catalog. This marks the version as hidden and rebuilds the catalog; it does not delete the Qanvas file, preview or metadata. Choose Restore to catalog to list it again. Review the generated Git changes and use Publish to GitHub before either change becomes public.

    Safety and privacy

    Official templates are hosted with the Qvitris documentation, checked against a SHA-256 value and validated before opening. They contain no credentials, organization-specific connections or personal data. Review an external API's terms before using it for production reporting.
