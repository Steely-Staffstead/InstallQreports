    Qvitris simulated heuristic/persona test — 30 roles

    Date: 25 November 2026

    Research status and method

    This is a simulated heuristic/persona test based on the current working copy, product behavior described in the changelog, implementation evidence and automated tests. It is not a test with 30 recruited people and contains no observed human sessions. The 30 roles represent different user goals, skill levels, environments and failure conditions.

    Each role was walked through its relevant create, edit, update, authenticate, publish, present, Viewer, export, failure and recovery tasks. Scores are directional (0–10) and useful for prioritization and comparison with the 13 November 2026 baseline; they are not statistically validated usability results.

    Evidence reviewed includes CanvasWeb/web/app.js, Formula Helper, Grid, Gantt, Viewer, publish, template, authentication and source-update modules; the Week 46–48 changelog; the comparison performance profile; focused Node/browser tests; and the previous 30-role report.

    Executive summary

    • Updated 30-role score: 8.9/10, up from 8.1/10 on 13 November.
    • Estimated core-task completion: 93%. Recommended for a controlled pilot for 28/30 roles.
    • Like-for-like original 20-role cohort: 9.0/10, up from 8.7/10.
    • Strongest improvements: Formula Helper and repeated Excel insertion, Entra authentication and token reuse, templates and source mapping, Gantt authoring, Grid/Excel interoperability, page-scoped export, clearer deployment choices, and presentation interaction.
    • Two roles remain below the normal pilot threshold: keyboard/screen-reader use (7.5) and very large reports (7.3).
    • This run does not qualify the working copy as a release build. Most focused static tests passed, but the managed environment prevented Edge-based test execution, several Grid tests need alignment with the current implementation, and a clean Debug/Release build was not established in this run.

    Automated evidence from this run

    • JavaScript syntax checks passed for app.js, chart-renderer.js, gantt.js and publish-wizard.js.
    • A focused sequential set of 42 test files executed 121 subtests: 90 passed and 31 reported failure.
    • The majority of reported failures occurred before application code ran because headless Edge could not start in the managed Windows sandbox (TransactNamedPipe, followed by a sandboxed taskkill credential error). These are classified as environment-blocked, not product passes or product failures.
    • Non-browser failures exposed test debt around the current Grid context-menu wording/theme markup and incomplete test VM browser stubs. These lower confidence in Grid regression coverage and are retained as an action item.
    • Debug and Release MSBuild attempts did not complete in the available shell session. A fallback dotnet build stopped before compilation because the current self-contained/project-reference configuration requires the Visual Studio build path. Build qualification is therefore inconclusive, not passed.
    • The existing comparison performance profile recorded no browser errors and approximately 15.2 MB used heap for its 9-page scenario. Its slowest page rendered in roughly 638 ms, dominated by repeated measure evaluation.

    Recommended priorities

    1. P0 — restore browser automation: run the critical Viewer, protected/safe-session, source-update, Gantt, secret and export suites in an unrestricted CI/desktop test runner.
    2. P0 — repair Grid regression tests: align context-menu assertions with the grouped design, supply complete browser stubs, and confirm theme-role markup and Excel export behavior.
    3. P0 — release-build proof: complete Debug/Release builds, verify web-asset hashes, install on a clean machine and run the installed-build smoke test.
    4. P1 — accessibility: add nonvisual chart/table summaries and browser-verified keyboard/object navigation.
    5. P1 — scale: benchmark 50 pages, 30 sources and 500 objects; define budgets for open, render, update and export.
    6. P1 — installed Office/Viewer matrix: exercise Excel, PowerPoint, Viewer and Creator across current and older supported versions.
    7. P2 — support/governance: add guided recovery decisions, rollback guidance and optional separation of publication approval from authorship.

    Interpretation

    The simulated result supports a controlled pilot for most user types and shows meaningful improvement since 13 November. It should not be cited as evidence that 30 real users achieved these tasks. Before a broad release claim, the environment-blocked browser suites, Grid regression tests, installed-build checks and the two weaker personas should be addressed or covered by a small observed usability study.
