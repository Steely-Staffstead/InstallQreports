    Save, Apply, Return and Update audit

    Status reviewed: 2026-11-11

    Completion language

    The application uses four different completion contracts. Labels should describe the contract instead of using an ambiguous generic OK or Done.

    Contract Meaning Dirty-state language Completion action
    Save Persist a file, reusable library item, connection or draft without changing the caller. Unsaved changes / Saved where the object has an independent save lifecycle. Save, Save as, Save to library, Save connection, or Save draft.
    Apply Commit a reviewed draft to its owner without fetching external data. Unapplied changes / No unapplied changes. Apply design, Apply mapping, or Apply selection.
    Return and apply Return a workspace result to the caller and close the workspace. Unapplied changes / No unapplied changes, plus a caller-aware breadcrumb. Apply to Qanvas, Apply to Query, or Apply to Excel.
    Update Execute a source request and replace its loaded data snapshot. Update required, Updating…, then a row/status result. Update source or Update affected.

    Apply & update is deliberately not a default workspace action. Source-definition changes are applied first; Qanvas then shows that the source needs an update. The only combined action retained is Save and refresh for an embedded Grid link, where saving the link and immediately reading the linked local range are one explicit operation.

    Primary workspace inventory

    Surface Save actions Apply/return action Update action Dirty/completion model Status
    Qanvas document Save, Save as Return when hosted by a caller Update source, global Update Document dirty state; source definitions separately set updateRequired Complete
    Query Workspace Save, Save as, SQL file, query workspace, source view, combined source Caller-aware Apply to Qanvas/API Designer/Excel None; applying a source definition marks it for update in Qanvas Separate saved-file/tab state and Unapplied changes state; cancel warns about unapplied work Complete
    API Workspace Save to library, Save connection Caller-aware Apply to Qanvas/Query/Excel Send is a preview/test request; source update remains in Qanvas Unapplied changes; library save does not clear caller apply intent; cancel warns Complete
    Measures Save draft Apply to Qanvas None Unapplied changes; discard confirmation; draft save remains local until Apply Complete
    Connections Save None Test does not save Independent connection editor lifecycle Complete for its single-owner contract

    Embedded designers and dialogs

    Surface Completion action Dirty/discard protection Assessment
    HTML designer Apply design Unapplied changes; discard confirmation Complete
    SVG designer Apply design Unapplied changes; discard confirmation Complete
    App designer Apply design Unapplied changes; discard confirmation Complete
    Standard visual designers Apply design Draft is isolated until Apply; some older designers do not display a textual dirty badge Functionally complete; textual status can be added incrementally
    API parameter mapping Apply mapping Modal draft discarded on Cancel Complete for a short modal transaction
    API flatten/path selection Apply selection Modal draft discarded on Cancel Complete for a short modal transaction
    Filters Apply values / Apply filter Modal draft discarded on Cancel Complete; applies local filter configuration, not a workspace return
    Embedded local table Save Unsaved changes / Saved; edit guards Complete
    Grid source link Save link; optional Save and refresh Dialog draft discarded on Cancel Intentional exception: local link save plus immediate local refresh

    Terminology checks

    • A workspace Save must never imply that its result was returned to Qanvas or Excel.
    • Apply to … identifies the caller and closes the workspace.
    • Apply design changes an object already owned by the current Qanvas document.
    • Update source performs data I/O and replaces the loaded snapshot.
    • Run, Send, Preview, Validate, and Test are non-persistent checks unless their surrounding editor explicitly says otherwise.
    • Cancel/close with a meaningful draft must either show No unapplied changes or ask before discarding it.

    Remaining review items

    The primary workspace model is complete. Remaining work is consistency polish rather than a missing workflow:

    1. Add a visible Unapplied changes badge to older generic visual designers that currently rely only on draft isolation.
    2. Continue replacing local generic labels such as Done or OK when a more exact Save, Apply, or Close contract is known.
    3. Keep combined Apply & update actions out of source workspaces unless a future flow explicitly previews the network/data replacement and its impact.
    4. Maintain the regression tests in workspace-completion-model.test.cjs and workspace-apply-flow.test.cjs whenever workspace buttons or return targets change.

    Conclusion

    The main Qanvas, Query, API and Measures workflows now share the intended completion language and distinguish persistence, returning a draft, and refreshing data. This initiative can be considered complete for primary workspaces; the remaining items are incremental UI consistency improvements in smaller modal designers.
