    Local queries and data

    Local data lets Qanvas and Query Tool work with manually entered tables, imported files, web files, saved remote-query results, and combinations of those sources without requiring a live database for every operation.

    Local source types

    Badge Type Meaning
    M Manual Rows entered and maintained locally.
    F File Imported CSV, text, or Excel data.
    W Web file File data imported from a remembered URL.
    V Source view A saved SQL or API query materialized as local rows.
    C Combined source A Mini SQL result built from local tables or views.

    Choose local — Local JSONL tables in Query Tool. Groups act like schemas, so qualified names such as [weather].[Temperature] or weather.Temperature can be used in previews, joins, and Mini SQL.

    Create and refresh local results

    Use Save as source view to preserve a remote SQL/API definition and its local result. Use Save as combined source for a reusable query across local tables and views. A source view refresh reruns its remote query; a combined-source refresh recalculates from its local dependencies.

    Update sources shows age and status and refreshes selected sources in dependency order. Refresh upstream views before combined results. Missing dependencies and cycles must be corrected before the chain can run.

    Imports and preparation steps

    CSV, text, Excel, and web imports can remember their source, comments, renamed or removed columns, types, and removed rows. Reopening or reimporting the source replays the remaining preparation steps. These steps prepare the table before a Mini SQL query consumes it.

    Local rows and definitions are stored on the computer or packaged with a portable Qanvas report where supported. Credentials remain external and should be managed through named connections and SecretManager.

    Continue with the complete Query Tool local-source reference or the Mini SQL guide.
