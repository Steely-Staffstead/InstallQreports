    Tiles and visual types

    Qanvas pages are assembled from tiles. Every tile can be positioned, resized, layered, duplicated, copied and pasted, and formatted from the Properties pane. Data-bound tiles select one document source; presentation tiles can remain independent of data.

    Data tiles

    Tile Use it for Main design surface
    Table Detailed records, selected fields, sorting, totals, and conditional formatting Table designer
    List Editable operational rows, task lists, choices, lookups, and dates List designer
    Matrix Grouped rows, hierarchies, subtotals, expand/collapse, and measures Matrix designer
    Chart Visual comparisons, trends, distributions, and KPI plots Chart designer
    Gantt Tasks, dates, groups, owners, progress, milestones, and dependencies Gantt designer
    Card One prominent value, caption, target, comparison, or delta Card properties
    Multi-card A reusable card layout repeated by a dimension, with multiple fields/measures per card Multi-card designer
    Report Grid Manually arranged statements, formulas, measures, ranges, and formatting In-tile grid editor

    Designer windows place compact property-group shortcuts above their previews. Use these shortcuts to open and focus the corresponding settings section without searching or scrolling through the full options pane. Preview elements that already link to a specific setting continue to work alongside the group shortcuts.

    When you add a new page, Qanvas shows the nine page-layout choices directly on the empty canvas. Choose a starting layout there, or use the page menu later to change the layout. The choices cover Blank, Title + content, Two columns, Main + sidebar, Overview + details, Dashboard, Project plan, Four tiles, and List + details. Workflow layouts show recommended tile types in their empty areas, but Qanvas waits for you to click Add tile before adding any content.

    Table, List, Matrix, Chart, Card, Multi-card, and Report Grid visuals can use source fields and Mini DAX measures. Gantt can use a linked source or keep an editable embedded task database. An embedded Gantt can expose its tasks as a Qanvas datasource for other visuals.

    Editable List

    Choose Add tile > List, then start from Basic or Task. Basic creates an Item field plus managed id, line_no, created_at, and updated_at columns. Task adds title, description, status, priority, owner, due date, and completion date. The designer can add or remove optional fields and configure text, multiline, numeric, Boolean, date/date-time, choice, and lookup types.

    An embedded List owns one manual-table source; rows are not copied into a second tile-only store. Expose as datasource controls whether other visuals can choose that source. A List can instead show an existing linked source, but linked rows are read-only until a write-back provider exists. Embedded rows are editable on the canvas, while Presentation editing is off by default and web exports remain read-only. Tab from the final editable cell creates the next row. Row commands support move, duplicate, delete, and task completion.

    The movable, resizable List designer applies valid changes immediately. Its Data, Fields, Layout, Appearance, and Interaction shortcuts focus the matching property group, and clicking a preview heading or cell opens the corresponding field setup. Drag the field handle or use its compact move controls to change column order. Resize columns directly from the live List header; that column is stored as a fixed pixel width while untouched Auto/percent columns continue to share the remaining space. Duplicating or copying an embedded List creates an independent owned source with the same rows; linked Lists retain their source reference.

    Each editable field can define a value used when a new row is created. Choice fields use their stored code, Boolean fields can default checked or unchecked, and date fields support dynamic Today or Current date and time values. The Task preset starts Status at Open and Priority at Normal. Appearance keeps column-header background and text colors separate, supports theme roles or manual colors, and can render header cells with rounded or square corners. The compact toolbar can independently show an optional list title and an optional search control; both the search caption and placeholder text are configurable. Editable controls inherit the row surface so text, choice, and date cells read as one row, while action buttons remain visually distinct. Dropdown arrows and calendar icons follow the active text color. Alternating rows are optional and can use either a canvas-theme role or a manual color. Grid/row-divider color and column-separator color are independent and can each follow a theme role or use a manual color. URL hover background is also theme-aware or manually selectable. URL fields can contain safe web or email links and internal document-page links. Use Choose… for a field default, or the arrow button/right-click menu in an editable row, to select either a web address or a Qanvas page. External links open in a new window; document links navigate inside the current report. A configured screen tip is shown as the readable link label and as its tooltip instead of exposing the stored URL. In Presentation mode, Add row and the row action buttons remain available only when Allow editing in Present mode is enabled.

    List Form: one record at a time

    In the List designer, choose Layout > View > Form · one record when a wide row is easier to work with as a form. The Form view uses the same source and fields as the normal List; it does not create another copy of the data. This is especially useful for test-case registration, findings, tasks and other records with long descriptions.

    Choose 1–6 form columns and set each column to Auto, percent or a fixed pixel width. In the preview, select a field and use its visual controls to move it, change its column, or increase and decrease its column span and row span. A long text control fills the height of its row span. Automatic controls follow the field type, including date pickers, choice lists, checkboxes, URL controls, numeric inputs and multiline text. Individual fields can be read-only when they should remain visible without allowing the user to change them.

    The record navigator moves through the rows that remain after source, page and tile filters. Turn on Follow List selection to use a normal List as a record selector: clicking a row updates Form views that use the same source. A linked List or Form reuses the selected shared source instead of creating an extra empty source, so one central register can support registration and filtered views on several pages.

    See the full table and matrix, Gantt, and Report Grid reference.

    Presentation tiles

    • Text supports formatted headings, paragraphs, bullets, interactive checklists, links, editable tables, code/diagram blocks, compressed inline pictures, parameter text, and source or measure values. Its safe formatted HTML is suitable for one-off static flow diagrams, outlined boxes, arrows, and code panels; use SVG for exact scalable or data-bound geometry.
    • Picture supports URLs and embedded local images with fit, fill-width, and fill-height sizing.
    • SVG content supports reusable graphics, bound text and values, and either theme-derived or explicit colors. Custom geometry uses the Manual template; built-in timeline, callout, and arrow-label templates remain preferable when they already match the requested visual.

    Text and Picture tiles do not require a datasource. Use them for titles, instructions, logos, illustrations, and navigation between report pages.

    Common tile behavior

    • Select one tile or drag around several tiles to move and align them together.
    • Use handles or the Properties pane for exact size and position.
    • Use Bring to front or Send to back when tiles or graphics overlap; their submenus also contain one-step Bring forward and Send backward actions.
    • Double-click editable text to work directly on the page.
    • Press and hold an action or hyperlink control in edit mode to select its object without following the action.
    • Use source, page, and tile filters at the appropriate scope.
    • To reuse an object's appearance, right-click it and choose Copy formatting. Compatible targets on the current page receive a green dashed outline, and page tabs show how many compatible targets they contain. Click one or more outlined objects, including on other pages, then choose Done or press Escape. The painter stays active for repeated use and only accepts the same visual family: chart-to-chart, card-to-card, table-to-table, and so on. It copies theme bindings, typography, borders, fills, renderers, conditional formats and other visual-specific appearance while preserving the target's datasource, fields, measures, formulas, filter binding, text/content and actions.
    • Ctrl+C copies the selected tile or graphic. You can change pages and press Ctrl+V repeatedly to place independent copies on the destination page; copied objects retain their data bindings and complete editable setup.
    • When a long Text or Multi-card tile is active, use Up Arrow and Down Arrow to scroll its overflowing content. At the tile boundary, the same keys scroll the canvas viewport.
    • In Presentation mode, double-click a tile to focus it and return to the prior view with another double-click, Escape, or Left Arrow.
