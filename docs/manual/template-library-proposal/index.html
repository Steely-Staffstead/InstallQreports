    Qanvas template library — phase 1

    Status: Implemented in Qvitris. This document records the design, publishing rules and planned follow-up phases.

    Recommendation

    Add an online Template library to the New-document experience. Host the catalog, preview images and .qanvas template files on the existing InstallQreports GitHub Pages site beside the help files. Keep the library out of the installer and let the Qanvas desktop host download, verify and cache templates on demand.

    The selected template must open as a new unsaved Qanvas, not as the remote template file. Its first Save therefore proposes the template's canvas name while leaving the published template unchanged.

    User workflow

    1. New opens a start dialog with Blank canvas, Templates, and optionally Recent.
    2. Templates are shown as preview cards with category, description, page format, required Qvitris version and data type.
    3. Search and filters cover common tasks such as finance, project status, KPI dashboard, management report, presentation and web report.
    4. Use template downloads and verifies the file, loads it as a new document and shows a short checklist for replacing sample data.
    5. The first Save uses the canvas name as the proposed .qanvas filename.

    The library should also be reachable from File/New from template after the initial start screen has been dismissed.

    Hosting structure

    InstallQreports/
  docs/manual/
  templates/
    catalog-v1.json
    finance-monthly/
      1.0.0/template.qanvas
      preview.webp
    project-status/
      1.1.0/template.qanvas
      preview.webp

    catalog-v1.json should contain only presentation and compatibility metadata:

    {
  "schemaVersion": 1,
  "generatedUtc": "2026-11-22T00:00:00Z",
  "templates": [
    {
      "id": "finance-monthly",
      "version": "1.0.0",
      "name": "Monthly finance report",
      "description": "P&L, balance and KPI pages with replaceable sample data.",
      "category": "Finance",
      "tags": ["management", "monthly", "P&L"],
      "locale": "en",
      "minimumQvitrVersion": "2026.11.22.0",
      "templateUrl": "https://steely-staffstead.github.io/InstallQreports/templates/finance-monthly/1.0.0/template.qanvas",
      "previewUrl": "https://steely-staffstead.github.io/InstallQreports/templates/finance-monthly/preview.webp",
      "sha256": "...",
      "size": 184320,
      "dataMode": "sample"
    }
  ]
}

    Versioned template paths prevent a cache from combining old metadata with a newly replaced file.

    Desktop implementation

    The WPF host should own network access. It can use the same bounded HttpClient pattern as the Enterprise updater and then send the parsed document to the existing web application.

    • Require HTTPS and the approved GitHub Pages host.
    • Limit catalog, preview and template download sizes.
    • Verify the template SHA-256 from the catalog before parsing.
    • Validate the Qanvas schema and minimum application version.
    • Open the result with _currentFile = null; never associate Save with the cached file.
    • Do not automatically refresh sources, run queries or execute App actions when a template opens.
    • Cache the last valid catalog, previews and verified templates under %LOCALAPPDATA%\QReports\CanvasWeb\Templates.
    • Refresh the catalog on explicit library open, with a short time-to-live such as 24 hours. Network failure should fall back to the last valid cache and must not delay normal Qanvas startup.

    Template content policy

    Start with two clearly labelled template types:

    • Layout template — pages, theme, tiles and placeholder fields, without real data or connections.
    • Example with sample data — embedded fictional rows that make charts and interactions immediately understandable.

    Published templates must not contain credentials, secrets, personal data, absolute local paths or organization-specific connection definitions. Remote APIs, SQL connections and MCP connections should be represented by replacement instructions rather than active configuration. Embedded HTML remains subject to the existing Qanvas sandbox.

    Each template should include a short first-page guide covering intended use, expected fields and how to replace sample data. This is more useful than a visually attractive file with unexplained bindings.

    Publishing and quality gates

    Extend the documentation publishing workflow so a template candidate is accepted only when it:

    1. passes the current Qanvas validator;
    2. contains no secrets, local paths or disallowed external hosts;
    3. opens without source refresh or authentication prompts;
    4. meets its declared minimum Qvitris version;
    5. has a preview image and useful description;
    6. has a unique immutable ID/version and generated SHA-256 hash.

    Catalog generation should be automated from per-template metadata files to avoid hand-maintained hashes and sizes.

    Evaluation

    Area Assessment
    Installer size Negligible; only library UI and downloader code ship with Qvitris.
    Release cadence Templates can be added or corrected without publishing a new installer.
    Offline use Good after first use when the last valid catalog and templates are cached.
    Security Good if downloads are host-restricted, hashed, size-limited and validated before loading.
    Maintenance Moderate; templates need ownership, screenshots, compatibility metadata and regression validation.
    User value High; users start from recognizable report patterns instead of a blank canvas.
    Main risk A template that looks complete but has unclear data replacement or stale bindings. Quality gates and an in-template setup guide mitigate this.

    Delivery phases

    1. Foundation: New dialog, catalog service, cache, validation, five curated templates and offline/error states.
    2. Data onboarding: expected-field metadata, field-mapping assistant and clearer replacement of sample sources.
    3. Managed catalogs: optional company-specific catalog URL and administrator allow-listing. Keep this separate from the official public library.

    Phase 1 now ships with the New dialog, host-restricted downloads, SHA-256 verification, local caching, offline/error states and five curated starters: Tender Pipeline, Project Planner, Management KPI Dashboard, Public Weather Snapshot and Nordic Growth Explorer. Ratings, user uploads and a public marketplace would add moderation, trust and compatibility costs without being necessary to address the current usability feedback.
