    QRep Excel Code

    QRep Excel Code is the worksheet language used to connect to data, run a query, and place the result in Excel. A report block normally has three parts: a connection row, one or more query rows, and an output row.

    Use this page to learn the language. Use the Formula Helper when you already know what you want and need to look up syntax or generate a correctly formatted table or subtotal definition.

    The smallest useful report

    This example uses the saved connection named demo, runs a SQL query, and returns a normal report table. The first row tells QRep where the data comes from, rows 2 and 3 contain the query, and row 4 defines the output.

    ABCD
    1conndemo
    2sqlSELECT country, population
    3sqlFROM country
    4tablecountrypopulation

    Select a cell in the block and choose Load selected line, or load the active sheet. QRep reads the definition and writes the result below the output row.

    The keyword is placed in column A. Its main value is normally placed in column B. Output columns begin farther to the right, allowing each Excel column to describe one returned field or measure.

    Connection rows

    Put the connection row above the query and output belonging to it.

    Keyword Purpose
    conn Uses a named database connection. Put the saved connection name in column B.
    model Uses the workbook Power Pivot model.
    powerquery Uses a supported Power Query connection definition.
    table Uses Excel tables through Mini SQL.
    file Uses a supported file source. Put its path or saved definition in column B.
    api Uses a saved API definition. See the API tool.
    connspec Uses an advanced connection specification stored as JSON.

    Connections are created and maintained from QRep > Connections. The Query Tool can also select a connection and write a valid report definition back to the sheet.

    Query rows

    Use sql, q, or query in column A. Put one query line in column B on each row. Keeping SQL on separate worksheet rows makes it easier to insert, remove, and inspect clauses.

    ABC
    1connsales
    2sqlSELECT region, SUM(amount) AS revenue
    3sqlFROM sales
    4sqlWHERE order_date >= '{{periodfrom}}'
    5sqlGROUP BY region
    6tableregion

    Aliases returned by SQL can be used as the output field names. Parameters such as {{periodfrom}} are replaced before execution; see Parameters.

    Output rows

    The output keyword controls how QRep places the query result in Excel.

    Keyword Result
    table A normal QRep report area with optional grouping, header, footer, and outline rows.
    dtable A dynamic structured Excel table.
    ptable A pivot-style result based on grouped fields.
    summary One compact summary row, commonly used for KPIs and measures.
    subtotal Grouped details with headers, footers, spacing, and Excel outline levels.
    load Loads data using the definition without the normal table presentation.

    Charts and Canvas definitions are handled by the Chart tool. DAX and model measures are covered in Mini DAX and measures.

    Keyword map

    The following map shows the worksheet codes you are most likely to encounter. Some are generated by a tool and are normally easier to maintain there than by editing their JSON manually.

    Area Codes Purpose
    Connection conn, model, powerquery, table, file, api, connspec Selects the data source for the report block.
    Query sql, q, query Adds query text from column B.
    Measures msr Stores the serialized measure definitions associated with a connection.
    Output table, dtable, ptable, summary, subtotal, load Selects how the result is returned to Excel.
    Chart chart, graph Stores chart output and definition data; normally maintained in the Chart tool.
    Companion column, crossfilter, parameter Describes an output column, applies a per-column filter, or supplies parameter/value pairs.
    Template + header, + footer, + footer1, + footer2 Adds formatting and summary rows to table or subtotal output.
    Control set, setreport, setpassword Defines parameters, report-sheet mappings, and protected-sheet loading on _control.

    msr, chart definitions, advanced parameter settings, and connspec can contain JSON. Prefer Query Tool, Chart tool, Parameter Manager, or Connection Manager when changing those definitions.

    Dynamic Excel table

    Change the output keyword from table to dtable when the result should be an Excel structured table. Column B supplies the table name.

    ABCD
    1conndemo
    2sqlSELECT country, population
    3sqlFROM country
    4dtabletblCountrycountrypopulation

    Useful output options are appended with semicolons:

    • group(continent,region) groups by fields;
    • filter(year=2026,amount>1000) filters the output;
    • sort(year ASC,region DESC) controls ordering;
    • toprows(20) limits the number of displayed rows;
    • noheader, nocrossfilter, and leftcolumn=4 change output behavior.

    For example: dtable;group(continent);filter(year=2026);sort(population DESC);toprows(20).

    Table headers and footers

    Template rows start with + in column A. The template type is placed in column B. Values in a header row override generated field names and options such as noheader. Remove the + header row when no explicit header is wanted.

    ABCD
    7table;group(continent)continentpopulation
    8+headerCONTINENTPOPULATION
    9+footer;outlinelabel(SUMMARY)$sum

    Common template rows include:

    Template Use
    header Supplies the displayed header text.
    footer Adds a final footer or summary row.
    footer1, footer2 Adds footer rows at specific subtotal levels.
    footer;outline Adds a footer participating in Excel outline grouping.
    footer;outlinec Adds an initially collapsed outline footer.

    Footer cells can use labels such as label(SUMMARY), aggregate shortcuts such as $sum, $count, and $avg, or an Excel formula beginning with =.

    Subtotal reports

    Use subtotal for hierarchical reports. List the grouping fields from the outer level to the detail level. Optional footer rows define what appears at each level.

    ABCDE
    12subtotal;group(continent,region)continentregionpopulation
    13+headerCONTINENTREGIONPOPULATION
    14+footer1;outlineclabel(TOTAL)$sum

    The Formula Helper has dedicated table and subtotal builders for choosing fields, aggregate functions, labels, header/footer rows, and outline behavior.

    Column definitions and crossfilters

    column defines a field or measure and can add agg(...), label(...), unit(...), filter, and display options. Supported aggregation choices include SUM, AVG, MIN, MAX, FIRST, and LAST.

    crossfilter is a companion row. Put a filter in each output column that it should affect. The values are written directly, without wrapping them in filter(...).

    ABCD
    20crossfilteryear=2025year=2026
    21summarycolumn;Revenue;agg(SUM);label(2025)column;Revenue;agg(SUM);label(2026)

    Filter syntax supports equality, >, >=, <, <=, and <>; | for alternatives; - for ranges; * or % wildcards; and NULL or NOT NULL. Comma-separated conditions are combined with AND.

    Parameters and control rows

    Use {{parameter_name}} in SQL, filters, text, and templates. Parameter definitions are normally stored on the _control sheet:

    ABCDE
    3setpyear2026TRUE{advanced settings JSON}
    4setreportTemplateReportpyear2026
    5setpasswordReportpassword

    set defines the current value, whether it is user-editable, and optional advanced settings. setreport maps a template sheet to a report sheet with optional parameter pairs. setpassword lets QRep temporarily unprotect and restore a report sheet during loading. See Parameters for the full setup.

    Recommended workflow

    1. Create and test the connection in QRep > Connections.
    2. Build and test the SQL in the Query Tool.
    3. Return the definition to Excel as table, dtable, summary, or another output type.
    4. Add grouping, filters, column definitions, and template rows.
    5. Use the Formula Helper to verify syntax or generate table/subtotal code.
    6. Load the selected line while developing, then load the full sheet.

    Generated rows such as xlinsr_tbl belong to the loaded result. Edit the QRep definition rows above them, then reload the report.
